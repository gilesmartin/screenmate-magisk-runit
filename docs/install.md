# Experimental staged installation plan

**This repository cannot safely install universally.** `sh scripts/install.sh` only prints a deterministic review plan, with `executes_device_changes: false`; `--apply` is rejected. Repeated generation does not touch any device or filesystem state. This is not an automated installation acceptance claim.

1. Confirm an already-authorized root ADB transport, Android 14 ARM64, enforcing SELinux, immutable product/system, overlayfs support and shared mount propagation. Have independent recovery access. Do not unlock, flash, remount partitions writable or change ADB as a packaging shortcut.
2. Obtain prerequisites from [dependencies](../dependencies.json). Verify the official Magisk APK outer checksum before extraction, then verify the three ARM64 executable hashes. Extract its own matching Manager stub privately; do not substitute an arbitrary Manager certificate. Existing Manager installation/version and signatures are a separate prerequisite, never silently replaced.
3. Obtain/build the pinned Termux runit sources and **librunit.so**, not just runsvdir. Verify ELF architecture/interpreter and all DT_NEEDED dependencies. The historical package checksum is reported, not independently recovered; stop if that exact artifact cannot be verified. Do not treat the current unrelated BusyBox Termux recipe as provenance for the installed Magisk BusyBox.
4. Review [reference scripts](../reference/source-manifest.json). They require explicit `SCREENMATE_REVIEWED_REFERENCE=yes` and replacement of a nonfunctional local-policy placeholder; that flag is not proof of safety. Do not run the references on production merely to test them.
5. During a separately approved maintenance window, capture pristine live SELinux kernel policy locally before any patch, retain it root-private outside source control and compute its target-local pin. An already patched running kernel is **not** a valid source for the pristine backup. Never use another device's policy or checksum. Plan storage and space requirements for private backups, logs and runtime state.
6. Stage only reviewed files under a root-owned service base, with directories 0700 and sensitive scripts/libraries 0600/0700 as applicable. Verify full parent ownership/non-writability, labels, executable and library paths. Preserve current bytes and service/mount states first. Keep automatic starts disabled until accepted.
7. Integrate a trusted independent boot entry using [the documented chain](boot-integration.md). Do not insert a new dependency into network boot or alter the existing watchdog without explicit approval. Field-test adapted scripts on a sacrificial compatible device before enabling production.
8. Only with fresh deployment approval, validate lifecycle/cleanup/root-app access and boot startup. Record live-context and app-namespace evidence separately. No grants, device deployment or reboot are part of this publication.

[Configuration](configuration.md), [recovery](recovery.md), [security](security.md) and [testing](testing.md) are mandatory reading.
